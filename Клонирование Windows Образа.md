### `Sysprep /generalize`

**Sysprep (System Preparation Tool)** — официальная утилита от Microsoft, которая подготавливает установленную ОС к клонированию.
#### Что делает `sysprep /generalize`:

|Действие|Зачем это нужно|
|---|---|
|Сбрасывает компьютерный SID|Генерируется новый при первом запуске|
|Удаляет уникальные данные (Machine GUID, WSUS ID)|Избегаем конфликтов управления|
|Очищает события и кэш драйверов|Чистая система для нового железа|
|Сбрасывает активацию Windows|Требует повторной активации (или использования KMS/MAK)|
|Запускает OOBE (Out of Box Experience)|Пользователь при первом входе задает имя, регион и т.д.|
#### 🔧 Типовой сценарий подготовки эталонного образа:
1. Установите ОС на виртуальную машину или тестовый ПК.
2. Настройте систему: обновления, приложения, базовые политики.
3. **Не создавайте пользовательские профили и не вводите ПК в домен на этом этапе!**
4. Запустите подготовку:
		C:\Windows\System32\Sysprep\sysprep.exe /oobe /generalize /shutdown /quiet `
	- `/oobe` — запуск первоначальной настройки при следующем старте.
    - `/generalize` — удаление уникальных данных (самое важное!).
    - `/shutdown` — выключение после завершения (образ снимается с выключенной машины).
5. После выключения **снимайте образ** (Acronis, Clonezilla, WIM, VHD и т.д.).
6. Разворачивайте образ на целевые машины → при первом запуске система сгенерирует новые уникальные параметры.
### 🛠️ Что насчет Acronis и других инструментов клонирования?
**Acronis, Clonezilla, Macrium Reflect и т.п.** — это инструменты **посекторного или файлового копирования дисков**. Они отлично копируют данные, но **не знают о внутренней логике Windows**.
- ✅ Они могут скопировать образ, подготовленный через `sysprep`.
- ❌ Они **не заменяют** `sysprep`. Если вы просто сделаете клон «живой» системы, вы получите все проблемы с дубликатами, описанные выше.
**Порядок действий с Acronis:**
	Установка ОС → Настройка → Запуск Sysprep /generalize → Выключение → 
	Загрузка в Acronis Boot Media → Создание образа → Развертывание
### 🧪 Как проверить, сработал ли Sysprep?
После развертывания образа и первого запуска новой машины:
	**Посмотреть текущий SID компьютера**
		wmic useraccount get name,sid | findstr /i "%computername%"
	**Проверить Machine GUID (должен быть уникальным)**
		reg query HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Cryptography /v MachineGuid
	**Убедиться, что ПК не в домене (если не вводили)**
		systeminfo | findstr /B /C:"Domain"

### 🏆 Почему ВМ лучше для создания «золотого образа» (Golden Image)

|Преимущество|Объяснение|
|---|---|
|**Аппаратная независимость**|ВМ использует виртуальное железо (стандартные драйверы). Образ, подготовленный в ВМ, легче разворачивать на разном физическом железе — `Sysprep /generalize` удалит привязки к конкретному оборудованию.|
|**Снимки (Snapshots)**|Перед запуском `Sysprep` можно сделать снапшот. Если что-то пошло не так — откатились за секунду, а не переустанавливаете ОС с нуля.|
|**Изоляция и безопасность**|Тестирование ПО, обновлений, скриптов в изолированной среде без риска для рабочей инфраструктуры.|
|**Быстрое клонирование**|В гипервизоре (Hyper-V, VMware) клонирование ВМ — это пара кликов или команда PowerShell, а не часы копирования через Acronis.|
|**Автоматизация**|ВМ можно управлять программно: сборка образа через Packer, автоматическое тестирование, интеграция в CI/CD.|
|**Экономия ресурсов**|Не нужно выделять отдельный физический ПК под сборку образа.|

### 🔧 Типовой рабочий процесс (пошагово)
#### 📦 Этап 1: Подготовка ВМ
1. Создать ВМ в гипервизоре (Hyper-V / VMware / VirtualBox)
2. Установить «чистую» Windows (с официального ISO)
3. Установить Интеграционные компоненты / VMware Tools
   → Это важно для корректной работы драйверов и управления
4. Не вводить в домен и не создавать пользовательские профили!
#### ⚙️ Этап 2: Настройка эталонной системы
5. Установить обновления Windows (желательно до актуального состояния)
6. Установить базовое ПО:
   - Браузеры, офисный пакет, антивирус (если требуется)
   - Агенты мониторинга, инструменты администрирования
7. Настроить локальные политики, если нужно
8. Очистить систему:
   - del /q/f/s %TEMP%\*
   - Очистка диска (cleanmgr /sagerun:1)
#### 🧹 Этап 3: Запуск Sysprep
:: Запуск от имени администратора
C:\Windows\System32\Sysprep\sysprep.exe ^
  /oobe ^
  /generalize ^
  /shutdown ^
  /quiet ^
  /mode:vm
  
📌 **Важно:** Ключ `/mode:vm` (для Hyper-V) оптимизирует процесс для виртуальной среды — пропускает некоторые шаги, не нужные в ВМ.
#### 💾 Этап 4: Экспорт/конвертация образа
| Гипервизор     | Способ экспорта                                                                                             |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| **Hyper-V**    | Экспорт ВМ → конвертация VHDX в WIM через `Export-WindowsImage` или использование готового VHDX как шаблона |
| **VMware**     | Конвертация в OVF/OVA или клонирование в шаблон через vCenter                                               |
| **VirtualBox** | Экспорт в OVA, или копирование VDI-файла                                                                    |

#### 🚀 Этап 5: Развертывание
- **Вариант А (ВМ)**: Развернуть как шаблон → новые ВМ наследуют настройки.
- **Вариант Б (физические ПК)**: Загрузить целевой ПК в WinPE → развернуть образ через `dism /apply-image` или Acronis → первый запуск → OOBE → ввод в домен.
### 🛠️ Пример: Сборка образа через PowerShell (Hyper-V)
 1. Создать ВМ
New-VM -Name "Win10-Reference" -MemoryStartupBytes 4GB `
  - NewVHDPath "C:\VMs\Win10-Ref.vhdx" -NewVHDSizeBytes 60GB `
  - Generation 2 -SwitchName "External"
  2. Подключить ISO и установить ОС (вручную или через autounattend.xml)
 3. После настройки — запустить sysprep из хоста
$vm = Get-VM "Win10-Reference"
Invoke-Command -VMName $vm.Name -ScriptBlock {
  C:\Windows\System32\Sysprep\sysprep.exe /oobe /generalize /shutdown /quiet
}
 4. После выключения ВМ — экспортировать диск
Export-VHD -Path "C:\VMs\Win10-Ref.vhdx" `
  -DestinationPath "D:\Images\Win10-Golden.vhdx"
### ⚠️ Важные нюансы при работе с ВМ

|Нюанс|Решение|
|---|---|
|**Драйверы для физического железа**|При развертывании на «голое железо» используйте загрузочный носитель с набором драйверов (интеграция в WinPE) или инструменты вроде MDT, которые подгружают драйверы динамически.|
|**Активация Windows**|После `generalize` активация сбрасывается. Для массового развертывания используйте **KMS** или **MAK-ключи**; для тестов — оценочную версию.|
|**Лицензирование ПО**|Убедитесь, что лицензии установленного ПО позволяют клонирование (некоторые привязаны к железу).|
|**Размер образа**|Перед захватом образа очистите диск: `sfc /purge`, удалите точку восстановления, используйте `dism /online /cleanup-image /startcomponentcleanup`.|

### 🔄 Альтернатива: «Динамическое» развертывание без образов
Современный тренд — **не хранить тяжелые образы**, а собирать систему «на лету»:

|Инструмент|Суть|
|---|---|
|**MDT (Microsoft Deployment Toolkit)**|Сценарии установки + драйверы + приложения = автоматическая сборка при развертывании|
|**WDS (Windows Deployment Services)**|Сетевая загрузка (PXE) + установка по сети|
|**ConfigMgr (SCCM)**|Полноценное управление жизненным циклом: от образа до обновлений|
|**Autopilot (для Windows 10/11 + Azure AD)**|Устройство получает настройки и ПО из облака при первом включении — образ вообще не нужен!|
👉 Для небольших сред достаточно связки **ВМ + Sysprep + PowerShell/DISW**, для крупных — **MDT/WDS** или **Autopilot**.

## ⚠️ Важное изменение (апрель 2026): WDS и boot.wim

С апреля 2026 года **Windows Deployment Services (WDS) больше не поддерживает «ручное» развёртывание через стандартный `boot.wim` с установочного диска** для новых версий ОС.

|Что изменилось|Что это значит для вас|
|---|---|
|`boot.wim` с ISO Windows 11/Server 2025|**Заблокирован** для использования в WDS|
|`boot.wim` с Windows 10/Server 2019|**Работает**, но с предупреждением|
|**Кастомные образы** (через MDT, ConfigMgr)|✅ **Полностью поддерживаются**|
👉 **Вывод**: Использовать «голый» WDS с установочного диска больше нельзя. Но **комбинация WDS + MDT (или ConfigMgr) работает отлично**, потому что они используют свои кастомные `boot.wim`.
## 🔄 Как работает PXE-загрузка (схема)
Клиент
   │
   ▼
1. Включается → BIOS/UEFI ищет PXE-устройство
   │
   ▼
2. Отправляет DHCPDISCOVER с PXE-опциями (Option 60: "PXEClient")
   │
   ▼
3. DHCP-сервер отвечает:
   ├─ Option 66: IP TFTP-сервера (или адрес WDS)
   ├─ Option 67: Имя файла загрузки (boot\x64\wdsnbp.com)
   │
   ▼
4. Клиент скачивает NBP (Network Bootstrap Program) через TFTP
   │
   ▼
5. NBP загружает BCD → загружает boot.wim (PE-среда)
   │
   ▼
6. В PE-среде запускается скрипт развёртывания (MDT/ConfigMgr/свой)
## 🛠️ Пошаговая настройка (классическая связка: WDS + MDT)
### 🔹 Шаг 1: Подготовка сервера (Windows Server 2019/2022)
**Установить роли (запустить от администратора)**
Install-WindowsFeature -Name Windows-Deployment-Services `
  -IncludeManagementTools
Install-WindowsFeature -Name DHCP -IncludeManagementTools
### 🔹 Шаг 2: Настройка WDS
**Инициализация хранилища и настройка**
Wdsutil /Initialize-Server /RemInst:"C:\RemoteInstall"

**Разрешить ответ всем клиентам (или только известным)**
Wdsutil /Set-Server /PxeResponsePolicy:All

**Добавить кастомный boot.wim от MDT (НЕ стандартный с ISO!)**
Wdsutil /Add-Image /ImageFile:"C:\MDT\Boot\LiteTouchPE_x64.wim" `
  /ImageType:Boot /FileName:"MDT_Boot_x64"

**Добавить install.wim (образ системы)**
Wdsutil /Add-Image /ImageFile:"C:\MDT\Captures\Win11_Reference.wim" `
  /ImageType:Install /ImageGroup:"Windows11"
  
  📌 **Важно**: `boot.wim` должен быть сгенерирован через **MDT** или **ConfigMgr**, а не взят с установочного диска.
### 🔹 Шаг 3: Настройка DHCP (если DHCP и WDS на одном сервере)
Если DHCP и WDS на **одном сервере** — просто разрешите прослушивание порта 67:
Wdsutil /Set-Server /UseDhcpPorts:No

Если **разные серверы** — настройте **IP Helper** на коммутаторе (предпочтительно) или добавьте опции в DHCP:

|Опция|Значение|Когда использовать|
|---|---|---|
|**60**|`PXEClient`|Только если клиенты не определяют PXE-сервер|
|**66**|`192.168.1.10` (IP вашего WDS)|Если нет IP Helper|
|**67**|`boot\x64\wdsnbp.com`|Если нет IP Helper|
⚠️ **Рекомендация**: Лучше использовать **IP Helper** на L3-коммутаторе, а не опции 66/67 — это надёжнее и не ломает другие устройства.

**Пример настройки IP Helper на Cisco**
interface Vlan10
 ip helper-address 192.168.1.10  # WDS-сервер
### 🔹 Шаг 4: Подготовка образа через MDT
1. Установите **ADK** + **WinPE Add-on** + **MDT**.
2. Создайте Deployment Share → импортируйте ОС → создайте Task Sequence.
3. Обновите образ загрузки:
В консоли MDT: правый клик на Deployment Share → "Update Deployment Share"
 → выберите "Completely regenerate the boot images"
 4. Полученный `LiteTouchPE_x64.wim` добавьте в WDS (см. Шаг 2).
### 🔹 Шаг 5: Тестирование
1. Включите тестовый ПК/ВМ.
2. Войдите в BIOS/UEFI → включите **Network Boot / PXE**.
3. При загрузке вы должны увидеть меню выбора образа.
## 🧪 Быстрая проверка работоспособности
#### На клиенте (в командной строке после PXE-загрузки):
ipconfig /all          # Проверить, получен ли адрес
ping 192.168.1.10      # Доступность сервера
net use \\192.168.1.10\REMINST  # Доступ к хранилищу
#### На сервере:
Get-WdsClient -DeviceName "TEST-PC*"  # Просмотр клиентов, запрашивающих загрузку
Get-EventLog -LogName "System" -Source "WDSServer" -Newest 20  # Логи WDS
## 🚨 Частые проблемы и решения

|Проблема|Вероятная причина|Решение|
|---|---|---|
|Клиент не видит сервер|Нет IP Helper / опций 66/67|Настроить relay или опции|
|Ошибка "TFTP timeout"|Брандмауэр блокирует UDP 69|Открыть порты: `69/UDP, 4011/UDP, 50000-65000/UDP`|
|Загрузка зависает на "Starting Windows"|Несовместимый boot.wim|Использовать образ от MDT, не с установочного диска|
|Клиент получает неверный образ|Неправильный приоритет в WDS|В консоли WDS → Properties → PXE Response → выбрать "Respond to all" или настроить фильтры|
|Ошибка активации после развёртывания|Сброшена активация после Sysprep|Использовать KMS/MAK или автоматизировать ввод ключа в Task Sequence|
## 🔄 Альтернативы «классическому» PXE

|Инструмент|Плюсы|Минусы|
|---|---|---|
|**MDT + WDS**|Бесплатно, гибко, хорошо документировано|Требует ручной настройки, MDT официально не обновляется|
|**ConfigMgr (SCCM)**|Полноценное управление, отчетность, обновления|Дорого, сложно в настройке|
|**FOG Project**|Open-source, веб-интерфейс, клонирование дисков|Меньше интеграции с AD, требует Linux-сервера|
|**Windows Autopilot**|Облачное развёртывание, не нужен образ|Требует Azure AD + Intune, только для Windows 10/11|
